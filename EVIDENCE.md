# Evidence and adoption record

**Status:** draft; observation date 2026-11-03. Eight primary sources inspected at the linked portions; project descriptions are author claims, not independent maturity ratings. No code run, experimental dataset acquired, license compatibility adjudicated, or benchmark validated.

1. [NASA Vision 2030 propulsion grand challenge paper](https://ntrs.nasa.gov/api/citations/20205008206/downloads/CFD2030IC_Propulsion_Grand_Challenge-final3.pdf), especially introduction and compression-system testing sections; its [text](https://ntrs.nasa.gov/api/citations/20205008206/downloads/CFD2030IC_Propulsion_Grand_Challenge-final3.pdf.txt) was read. Historical roadmap calls for component coupling and targeted common-model experiments, and notes scarce detailed compressor measurements. It is not evidence this reduced-order design is validated.
2. [Fidalgo, Hall and Colin, Rotor 67 fan-distortion study](https://doi.org/10.1115/1.4003850): publisher abstract as deposited at [Crossref](https://api.crossref.org/works/10.1115/1.4003850) describes 120-degree inlet total-pressure distortion, full-annulus unsteady CFD, and comparison with measurements. It identifies swirl and redistribution effects neglected by the proposed model. Abstract and citation are public; full experimental inputs, uncertainty, raw measurements, access terms and redistribution rights were not established. No complete reusable benchmark is assumed.
3. [OpenMDAO/pyCycle](https://github.com/OpenMDAO/pyCycle): thermodynamic cycle library on OpenMDAO; candidate cycle adapter, subject to version and license review.
4. [NASA T-MATS](https://github.com/nasa/T-MATS): thermodynamic/control blocks in MATLAB/Simulink; integration entails that runtime. Repository states Apache 2.0 for software, not universal data rights.
5. [NASA turbo-design](https://github.com/nasa/turbo-design): streamline radial-equilibrium turbomachinery design, a possible geometry/design comparator, not the same model. Repository identifies NASA Open Source Agreement; verify actual code and data terms.
6. [FullFlow](https://github.com/saakethramoju/FullFlow): general steady/transient network approach, not CFD. Repository identifies GPL-3.0; assess compatibility before reuse.
7. [NASA AGTF30](https://github.com/nasa/AGTF30): geared-turbofan system model built using T-MATS and MATLAB/Simulink; useful reference, not a direct single-component distorted-inflow benchmark.
8. [SU2](https://github.com/su2code/SU2): PDE/CFD suite, potential higher-fidelity comparison subject to matched configuration and numerical verification; not experimental validation.

The sector area-scaling rule and common-discharge-total-pressure closure are proposed modelling assumptions, not established by these sources. In particular, the Rotor 67 abstract's swirl and flow redistribution motivate rejecting unsupported inputs and requiring domain review of a physical basis or alternative closure before prediction. No such review or comparison has been performed.

## Adoption, rights and governance

P0 must name a technical maintainer, data steward and independent reviewer, and record a decision on project license and each upstream dependency. Code license, map ownership, geometry, measurements, derived data and redistribution permissions are distinct; exclude restricted materials from releases and document a reproducible access path where permitted. Evaluate export controls and institutional agreements rather than infer permission from public visibility. Seek a research partner for measured distorted-inlet fields, boundaries, hardware configuration and uncertainties, with a held-out validation set and written reuse permissions. Until then validation is BLOCKED.

For adoption, publish only after P6: a minimal rights-cleared example, pinned environment, limitations and result schema, plus contribution/review policy, code of conduct, private security contact, release/versioning and archival ownership. A maintainer reviews changes to contracts, data and claim boundaries; threshold changes require the freeze policy. Revisit architecture when a verified adapter or new independent data changes the tradeoff. No promise of novelty, performance or certification readiness.
